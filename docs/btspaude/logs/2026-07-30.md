# CDet–ECal timing-cut study review: 2026-07-30

The `plotECalCDetTimeCutStudy()` routine was reviewed against its requested selection and plotting behavior. It operates on the nested fourth-pass good-hit vectors, preserving event boundaries; defines `dt = tECal - tCDetLE`; and applies the inclusive `dtMinCut <= dt && dt <= dtMaxCut` requirement as its only additional hit-quality cut. The selected logical pixel ID is used only when filling the requested single-pixel LE plot.

The routine provides the uncut delta-t versus logical-pixel plot, uncut delta-t distribution with cut lines, post-cut LE/TE/TOT plots, selected-pixel post-cut LE plot, per-pixel hit efficiency with binomial uncertainty, and optional uncut delta-t-versus-TOT diagnostic. Explicit routine arguments control histogram ranges and bin width.

ROOT compilation succeeded. Synthetic tests confirmed inclusive timing-window endpoints, baseline and passing counts, selected-pixel counts, optional-diagnostic entries, and per-pixel efficiencies. Existing compiler warnings were outside this routine.

The project leader further specified that plotting-routine function signatures and ROOT histogram/canvas constructor calls should remain on one line. This preference is now part of the working agreement.

The reusable `IsCrossTargetRun()` helper checks a supplied run number against `scripts/cdet/runs.txt`. The efficiency canvas uses it to display `Cross-target run <number>` when the active `gRunNumber` is listed. A listed run and an unlisted run were both tested to confirm that the helper and annotation behave conditionally. Other plotting routines can reuse the same helper without duplicating file-reading logic.

While awaiting collaborator feedback on rate studies, timing work resumed. The timing-cut routine now includes post-cut ECal ADC time versus CDet LE plots for all detector hits and for the selected logical pixel ID. The per-pixel efficiency calculation, graph, canvas, cross-target annotation, and printed overall efficiency are retained in comments but temporarily disabled. Synthetic testing confirmed two all-detector entries and one selected-pixel entry for a controlled sample with two passing hits.

An uncut ECal-minus-CDet delta-t distribution for the selected logical pixel ID was also added, with the same timing-window markers as the detector-wide distribution. The logical-pixel requirement is only a plotting selection; the histogram includes selected-pixel baseline hits both inside and outside the trial delta-t window.

## ECal reconstructed-cluster rate work

The cross-target macro now collects every finite stored `earm.ecal.clus.e` entry over every processed event before electron/elastic selection. `calculateECalClusterRate()` performs the calculation only when explicitly called, using a caller-selected threshold and `processed events × 250 ns` as the observed time. It counts multiple qualifying clusters in one event, reports the Poisson error `sqrt(N)/time`, prints the result, and draws the stored cluster-energy spectrum with the threshold and rate. It creates no CSV or separate ROOT result file.

Automatic data-derived energy limits were removed. The caller now supplies the requested bin width and independent `binMinGeV`/`binMaxGeV` display limits; these bounds do not alter the rate selection. Commit `51834b3` (`Add configurable ECal energy bin range`) was pushed to the SBS-replay `tdccalib` branch.

Inspection found two upstream limitations. The active ECal database has `earm.ecal.emin_clTotal = 0.5`, so replayed cluster arrays contain no clusters below 0.5 GeV. Separately, `SBSCalorimeter` defaults its stored-cluster cap to ten: `earm.ecal.nclus` can exceed ten while `earm.ecal.clus.e` remains size ten. The analysis detects and reports that mismatch but cannot recover unstored clusters. The project leader is awaiting ECal-expert feedback on whether the ten-cluster limit is intentional; no database or offline change was made.
