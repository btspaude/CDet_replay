# One-bar CDet pixel timing-offset extraction: 2026-08-04

The cross-target calibration macro now includes `extractCDetBarPixelTimingOffsets()` as a post-analysis diagnostic. The initial implementation intentionally processes one 16-pixel bar so the fit and correction method can be checked before it is expanded to all 168 bars. Its `pixelBase` argument accepts any physical logical pixel ID and normalizes it to the first pixel in that bar; for example, 485 selects IDs 480–495.

The routine uses the nested fourth-pass baseline vectors and defines `dt = tECal - tCDetLE`. It applies an inclusive event-level ECal energy selection using `v_GoodECalE`, filled from `earm.ecal.e`, with defaults of 1–12 GeV. Delta-t histograms default to 0–130 ns. Each instrumented pixel is fit over caller-supplied limits, defaulting to 65–105 ns, with `gaus(0)+pol1(3)`. Known unused physical pixels are classified without fitting. Configurable checks cover fit-region statistics, ROOT fit status, finite parameters and uncertainties, centroid proximity to the fit boundary, Gaussian width and amplitude, NDF, and chi-square per NDF.

The 4-by-4 fit canvas shows all 16 pixel histograms. Only fits passing the quality checks are drawn. For valid fits, the fitted centroid with uncertainty and chi-square/NDF are appended to ROOT's existing top-right statistics box alongside Entries, Mean, and Std Dev. The appended lines inherit the automatic ROOT font, size, color, and alignment, so they resize with the default statistics. Invalid fits show no curve or custom message; detailed failure reasons remain in the printed summary and optional candidate table. The selected-pixel delta-t fit in `plotECalCDetTimeCutStudy()` uses the same statistics-box helper.

Reliable fitted centroids define an inverse-variance-weighted, bar-local reference `mu0`. The candidate relative correction is `c_i = mu_i - mu0`; under the proposed convention `tCDet_i' = tCDet_i + c_i`, the corrected difference is `dt_i' = dt_i - c_i` and its centroid is `mu0`. This bar-local reference is only for validating the extraction method. A detector-wide anchoring convention remains to be chosen before the eventual all-bar result can be treated as calibration constants.

A separate summary canvas shows centroids, candidate corrections, widths, fit-region entries, chi-square per NDF, validity codes, and the before/after centroid distributions. Repeated calls use unique ROOT object names. By default the routine only draws and prints diagnostics. `saveFitCanvases=true` writes the bar fit and summary PDFs beneath a run/stage subdirectory; `saveCandidateTable=true` writes a clearly labelled candidate diagnostic table. The table writer refuses the active calibration filename and `CDet_calibration.dat`; the routine never applies a correction or changes a database.

ROOT ACLiC compilation succeeded. A synthetic test invoked the routine with pixel 485, confirmed normalization to base 480, correctly excluded the two unused pixels in that bar, fit all 14 instrumented channels, recovered the imposed centroid trend, produced both optional PDFs and the candidate table under `/tmp`, and confirmed the proposed correction sign. Existing compiler warnings were outside this routine.
