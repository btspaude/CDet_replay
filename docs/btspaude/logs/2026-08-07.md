# Pixel-level production timing offsets: 2026-08-07

The active cross-target calibration workflow now derives and applies one timing offset per physical CDet logical pixel instead of one offset per 16-pixel bar. The production method itself is unchanged: `plotAllTDC()` fits the global good-hit CDet leading-edge spectrum and each sufficiently populated pixel's good-hit CDet leading-edge spectrum, then defines the additive residual as `mu_all - mu_pixel`. The experimental `ECal - CDet` Gaussian-plus-linear timing-offset extraction remains a separate diagnostic and is not used by the calibration stages.

The cross-target master stores 2,688 corrections and hit counts, applies them directly by logical pixel ID to raw and good LE/TE values, and writes zero-based IDs under `[PixelOffsets]`. Known unused pixels and pixels with fewer than 20 entries receive zero residual and remain explicit in the complete 2,688-entry file. Loaded constants are accepted only when all entries are present. Legacy `[BarOffsets]` sections are ignored with a warning rather than reinterpreted.

Calibration stage numbers and driver function calls are unchanged. Cross-target driver labels now refer to pixel offsets. The hydrogen master and drivers, legacy macros, and archived calibration macros were intentionally left unchanged; hydrogen will be reconciled after the current tests mature. Existing calibration files with `[BarOffsets]` must be regenerated through the cross-target pixel-offset workflow.
