# 2026-10-19 — Load-once pulse-vector analysis

The user requested review of the Markdown under `docs/btspaude` and
`gocdetscripts`, then implementation of the Desktop pulse-vector refactor
specification. `gocdetscripts` resolves to the SBS-replay `scripts/cdet`
directory. Historical notes were treated as dated evidence; the current macro,
replay source and actual input branch schema governed the implementation.

Created a separate `Plot_CDet_PulsePixelTiming_Vectors.C` and copied
`CDet_run6077_pulse_pixel_timing_vectors.conf`. The loader stores every selected
event and every pulse-prefixed field before cuts. Four independent functions
reread configuration and analyze timing, LE/ToT, occupancy and projection
response from the shared vectors. Dataset changes require explicit reload.
Original functions/products remain separate; no replay or calibration changes.

The actual Run 6077 schema matches the documented 33 fields, all Double_t.
Additional numeric pulse fields are dynamically discovered and retained with
their native types. See the [complete guide](../../../git-repo/sbs_devel/SBS-replay/scripts/cdet/Plot_CDet_PulsePixelTiming_Vectors.md)
for all branch mappings, correction states, exact ROOT commands, implementation
layout and validation limits. The existing untracked scripts catalog was
updated locally to link to that guide; it is excluded from this change’s commits.

ROOT 6.40 validation passed on 1,000 real Run 6077 entries and a synthetic
10-event sample split across a base file and rollover part. The drivers compare
114 histograms with ellipse disabled and 117 enabled, including all flow bins,
entries, errors and axes, plus both projection-fraction graphs. Repeated calls,
cut edits without reload, timing-only isolation, dataset mismatch, replacement
reload, zero-pulse reference events, duplicate-pixel occupancy, extra primitive
types, NaNs and inconsistent file schemas were checked. Reader-value comparisons
are bit-exact for all Double_t pulse and ECal fields. Initial ROOT array-status
checks were corrected during testing; the delivered version uses normal array
access and the underlying value-reader status.

The real sample contains 488,252 pulses, mean multiplicity 488.252 and maximum
563. Estimated cached-vector allocation is 108.767 MiB, excluding allocator,
map and ROOT/process overhead. Load wall time was 0.277 s; the cached full-suite
repeat took 0.394 s versus 0.707 s for the original full pass. These are sample
measurements, not a controlled benchmark or a full-run memory qualification.
At this multiplicity, one million events would require roughly 106 GiB before
excluded overheads. Use a small explicit entry limit first. The inherited large
configuration limit was preserved, and a full-run cache was not attempted.

Original macro/configuration SHA256 values remained unchanged. No commits,
tags or branches were created. Unrelated pre-existing work was preserved.
Validation configurations, ROOT fixtures, build products and plots were kept
under `/private/tmp/cdet_vectors_check`, not added as repository plot products.
